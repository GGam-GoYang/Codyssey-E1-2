# 설계 및 복구 안내

## 클래스와 모듈 책임

`Quiz`는 한 문제의 question/choices/answer/source를 묶고 display와 check_answer를 제공합니다. `QuizGame`은 여러 문제와 최고 점수·완료 여부를 보관하며 메뉴와 저장 흐름을 조정합니다. 데이터와 관련 동작을 묶으면 문제 표현을 재사용하고 게임 관리와 구분할 수 있습니다. `Quiz.from_dict`는 딕셔너리를 객체로 바꾸는 규칙을 한곳에 모읍니다.

입력은 input_utils, 파일 구조 검증은 validators, 공통 화면 출력은 output_utils에 분리합니다. 검증 규칙 변경이 게임 순회나 파일 쓰기까지 흩어지지 않도록 합니다. 저장 성공 여부를 반환하는 save_json과 사용자에게 알리는 save_notice도 구분합니다.

## 입력 검증

숫자 입력은 strip으로 공백을 제거하고 빈 문자열, int 변환의 ValueError, 허용 범위 밖의 정수를 순서대로 처리합니다. 오류마다 안내하고 다시 입력받습니다. 문자 입력은 공백만 있는 값을 거부하지만 정상 문자열의 앞뒤 공백까지 제거해 저장하는 구현은 아닙니다. 등록 확인은 y/n/c를 사용하며 종료 확인에서는 c를 허용하지 않습니다.

validate_state는 최상위 dict, quizzes의 list 여부, 각 문제의 필드, high_score의 정수·0 이상, has_played가 존재할 때 bool 여부를 검사합니다. bool은 int의 하위 타입이므로 answer/high_score는 type(...) is int로 구분합니다. 현재 코드에서 has_played가 없으면 False를 사용하며 과거 점수로 완료 여부를 추론하지 않습니다.

## 종료 처리 범위

메뉴 반복 안에서 KeyboardInterrupt(Ctrl+C)나 EOFError(입력 스트림 끝)가 발생하면 exit_quiz로 넘어가 저장을 시도합니다. 저장 성공 시 SystemExit로 종료합니다. 실패하면 y/n으로 확인하고 n이면 메뉴로 돌아갑니다. 확인 중 다시 Ctrl+C/EOF가 발생하면 미저장 안내 후 종료합니다. EOF는 시그널이 아니며 signal 모듈이나 SIGTERM 처리기는 구현하지 않았습니다.

시작 파일 로드는 메뉴 반복문보다 먼저 실행됩니다. 종료 예외 처리는 메뉴 반복문에 적용됩니다.

## 원본 복구 방법

1. 오류 안내와 백업 파일명(state-backup-날짜시간.json)을 확인합니다.
2. 백업 파일을 보존합니다. 백업에 실패했다면 현재 원본을 별도 보관하고 읽기 권한·경로 등을 점검합니다. 읽기 실패가 반드시 파일 손상을 의미하지는 않습니다.
3. 프로그램을 종료합니다. 백업이 성공한 경우 종료 저장으로 state.json은 기본 데이터 기반 상태로 교체될 수 있으므로 원본 백업을 먼저 확보합니다.
4. 프로그램이 꺼진 상태에서 백업 사본의 JSON 문법·필드 구조를 수정합니다. 백업 원본 자체는 보존합니다.
5. 수정한 사본을 state.json으로 두고 다시 실행하여 목록과 점수를 확인합니다.

권한 오류 시 프로젝트 폴더와 파일의 읽기·쓰기 권한, 다른 프로그램의 파일 점유, 디스크 공간을 확인합니다. 무조건 관리자 실행이나 광범위한 권한 변경을 요구하지 않습니다. save_blocked는 이번 실행에 유지되므로 원인을 해결한 뒤 재실행해야 합니다.

## 커밋 단위와 메시지

기능 구현·수정·문서 정리 등 설명 가능한 변경 단위를 커밋으로 묶습니다. 메시지는 다음과 같이 변경 목적과 내용을 함께 표시합니다.

- Feat : 추가한 기능
- Fix : 해결한 오류
- Refactor : 동작을 유지한 구조 개선
- Docs : 변경한 설명·증빙

테스트로 생긴 임시 파일이나 개인 데이터 변경은 의도한 코드 수정과 분리해 검토합니다.
